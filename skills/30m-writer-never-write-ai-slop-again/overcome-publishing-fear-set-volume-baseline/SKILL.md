# Overcome Publishing Fear and Set a Volume Baseline

Unblock publishing paralysis by separating "does this add value" from "is this original," and by establishing a volume target before chasing quality.

## Quick Start
When a user says "I'm scared to publish because my content isn't unique/my voice isn't good enough," respond by: (1) reframing the real question as "does this drive value for the reader," not "has this exact idea existed before," and (2) assigning a concrete daily volume baseline (e.g., 5 pieces/day) to remove the decision paralysis of "how much is enough."

## Core Workflow

**Trigger 1: User expresses self-doubt about voice/originality ("I don't like my voice," "this has probably been said before")**
1. Acknowledge that most viral/successful content is NOT novel — it often restates known ideas (e.g., "a Wikipedia article summarized" or an AI-generated take on a common opinion).
2. Redirect the evaluation criteria: ask "What game are you trying to play?" — i.e., is the goal engagement/reach, or is it driving real value to the reader?
3. Tell the user: judge content by value delivered, not by whether the idea is unprecedented. Repetition of good ideas in a clearer or more useful form still counts as valuable content.
4. Give permission to publish: content doesn't need to be original to be worth publishing — it needs to be valuable.

**Trigger 2: User asks "how much should I be posting?" or shows paralysis about volume**
1. Do NOT let the user optimize quality before establishing quantity — volume is baseline infrastructure.
2. Assign a concrete, non-negotiable numeric target (e.g., "five pieces per day") rather than a vague guideline like "post often" or "post consistently."
3. Frame this target as the floor, not the ceiling — quality optimization happens on top of a volume baseline, not instead of it.

## Techniques

**Reframe question technique:**
- Bad question (causes paralysis): "Is this idea original enough to publish?"
- Good question (drives action): "What game am I trying to play — reach or value? Does this add value?"

**Value vs. novelty distinction:**
- IF content restates an existing idea clearly and usefully THEN it can still be valuable and worth publishing.
- IF the user is blocked purely because "someone already said this" THEN tell them novelty is not the bar — value delivery is.

**Volume-first framing:**
- IF a user has no baseline production habit THEN assign a specific number (e.g., 5/day) instead of a qualitative target.
- IF a user is optimizing for quality with near-zero output THEN redirect them to hit the volume floor first, because volume is prerequisite infrastructure for quality to compound.

## Anti-Patterns
- NEVER validate the paralysis-inducing question "has this been said before?" as the deciding factor for whether to publish — it stalls output indefinitely because almost everything has been said before.
- NEVER give a vague volume recommendation like "post regularly" or "post as much as you can" — vague targets don't resolve decision paralysis; concrete numbers do.
- NEVER let a user chase originality/quality perfection before they've established a volume baseline — this inverts the correct sequence (volume first, then optimize).
- AVOID equating high engagement (likes, virality) with genuine value — some viral content is just repackaged existing information (e.g., "Wikipedia summarized" or ChatGPT-generated essays on common takes); use value-to-reader as the real metric, not vanity metrics.

## Edge Cases & Error Handling
- If the user conflates "getting a lot of likes" with "creating real value," clarify these are separate axes — content can go viral without being valuable, and valuable content doesn't require virality to be worth publishing.
- If the user resists a numeric volume target as arbitrary, note it functions as a forcing mechanism to overcome analysis-paralysis, not as a permanent quality standard.
