# Use AI to Repeat, Not to Write or Think

AI's job in writing workflows is repurposing the writer's own existing words across formats — never inventing original thoughts or first-draft prose.

## Quick Start
When a user wants AI help with a writing task, ask: "Do you already have this idea written or said somewhere (notes, transcript, past post, voice memo)?"
- If YES → feed that source material to the AI and have it repurpose/reformat it.
- If NO → have the user write or dictate the core thinking FIRST (even roughly), then bring AI in to reshape it.
- NEVER let AI generate the original argument, opinion, or insight from a blank prompt with no source material.

## Core Workflow

**Trigger: User asks "should I let AI write this for me?" or similar blank-page request.**
1. Identify whether original thinking already exists in some form (transcript, voice note, old post, DM reply, meeting notes).
2. If it exists: extract that raw material as the source input for AI.
3. If it doesn't exist: STOP. Direct the user to generate the raw thinking themselves first (write badly, ramble into a voice memo, answer a question out loud) — this is not optional.
4. Only after raw material exists, use AI to: repurpose it into a new format, adapt it for a different platform, or restructure it — using the writer's own phrasing as the primary building blocks.
5. Treat AI's role as translation/repackaging of approved content, not authorship of new content.

**Trigger: User complains "the AI output doesn't sound like me."**
1. Diagnose: the AI was likely asked to originate content from a bare prompt instead of being given the user's own words to repurpose.
2. Fix: go back to source material the user actually wrote or said, and re-run the task as a repurposing task, not a generation task.

## Techniques

- **Commodity vs. point-of-view framing**: A commodity tool just accomplishes a task (e.g., "write me a post about X"). A point-of-view tool/method enforces a specific way of executing the task (e.g., "repurpose MY existing words into a post"). ALWAYS favor the point-of-view method for voice-sensitive writing.
- **Source-first rule**: IF no source material exists, THEN the AI step is blocked until the human produces raw material (draft, transcript, dictation).
- **Repurposing over drafting**: IF source material exists, THEN prompt AI explicitly to reuse/adapt existing phrasing rather than "write about" the topic generically.

## Anti-Patterns

- NEVER prompt AI with only a topic or blank instruction ("write a LinkedIn post about X") because it forces the AI to originate thinking, producing generic "slop."
- NEVER treat AI as a thinking partner that invents the core argument — it should only be given a stance/argument that already exists.
- NEVER accept "doesn't sound like me" as a prompting problem alone — it is usually a missing-source-material problem.

## Edge Cases & Error Handling

- If the user has no existing material and is in a rush: require at minimum a rough spoken/typed brain-dump before invoking AI — do not skip this step even under time pressure.
- If the user insists AI "just write it," warn that this reproduces commodity/generic output indistinguishable from any other user's AI output, undermining the point-of-view/voice goal.
